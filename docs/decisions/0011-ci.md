# 0011. Continuous integration on GitHub Actions

- Status: Accepted
- Date: 2026-11-08

## Context
`tests/run.sh` only ran on the owner's machine (Debian under WSL2, Bash 5.2). The project
promises Linux **and** macOS (Homebrew Bash) and a minimum of Bash 4.2 (decision 0008),
none of which was ever checked automatically. The suite once hung only when run from a
real terminal (decision 0009), which agents never see.

## Decision
`.github/workflows/tests.yml` runs on every push to `main` and every pull request:

| Job | Runs |
|---|---|
| `linux` | `bash -n`, `tests/run.sh`, then again under `script -qec` (pseudo-terminal) |
| `macos` | the same with Homebrew Bash (put first in `PATH`); BSD `script` has no `-e`, so the pseudo-terminal run is checked on its ` 0 failed` summary |
| `bash-versions` | `tests/run.sh` with Bash 4.2 in the official `bash:4.2` Docker image (Alpine, GNU tools added with `apk`), and `main.sh` under `bash:4.1` must exit 1 with the version message |

Every job has a timeout, so a test waiting on a prompt fails instead of hanging.
`bash-versions` starts as `continue-on-error`: it could not be run before the first push
(building an old Bash locally was not allowed). Remove it once the job has passed.

## Alternatives considered
- *Compile Bash 4.2 from source in CI*: slower, and old Bash sources need many compiler
  flags with a recent GCC. The Docker images are maintained upstream.
- *Only Linux*: macOS is a promised target and has BSD tools (`sed`, `script`, `mktemp`
  under `/var` → `/private/var`); only a real macOS run catches those.
- *Other CI services*: the repository is on GitHub; Actions needs no account or secret.

## Consequences
A red CI blocks nothing by itself, but the owner reviews pull requests with its result.
Tests must stay runnable on BSD tools and BusyBox-based images with GNU tools added; use
physical paths (`cd -P`) for temporary directories.
